* * * * *

**🔑 Core Constraints (DO NOT VIOLATE)**
----------------------------------------

1.  **The audit kernel must remain deterministic**

    -   Rules trigger based on explicit inputs

    -   No probabilistic reasoning

    -   No "AI judgment" of compliance

2.  **No legal advice**

    -   Output is a *risk assessment*, not certification

    -   Conservative defaults

    -   Unknowns → risk, not pass

3.  **No RAG-driven decisions**

    -   RAG (if used) is strictly read-only for explanations

    -   Compliance outcomes come only from rules

4.  **Preserve auditability**

    -   Every conclusion must trace back to:

        -   inputs

        -   metadata

        -   triggered rules

        -   legal citations

* * * * *

**🎯 Objective**
----------------

Adapt the existing EU AI Act audit kernel to produce a **HIPAA AI Risk Assessment** for AI use cases involving potential PHI exposure.

The end result should:

-   Accept a HIPAA-specific AI use case intake

-   Apply a deterministic HIPAA ruleset

-   Output:

    -   Risk classification (LOW / NEEDS REVIEW / HIGH)

    -   Triggered safeguards

    -   Clear remediation checklist

    -   Exportable report structure

---------------------------------------------------------------------

Create a new intake schema **alongside** the existing ModelProfile:

```

  use_case_name: string

  ai_function: "chat" | "summarization" | "transcription" | "coding" | "other"
```

**🧩 Step 3 --- Implement HIPAA v0 Ruleset (10--15 Rules)**
--------------------------------------------------------

Create a **new ruleset file** (do not overwrite EU AI Act rules).

Rules must:

-   Be explicit

-   Be boolean

-   Reference HIPAA Security / Privacy Rule sections

-   Fail conservatively

### **Example Rule Structure**

```
RULE_HIPAA_001 {
  condition:
    phi_involved === true &&
    vendor.baa_available !== true
  outcome:
    risk = "HIGH"
  citation:
    "45 CFR §164.308(b)(1)"
  explanation:
    "PHI is disclosed to a vendor without an active Business Associate Agreement."
}
```

### **Required Rule Categories**

Include rules for:

-   PHI exposure

-   Missing BAAs

-   Logging of PHI

-   Undefined retention

-   Undocumented access controls

-   Use of AI vendors in production with PHI

-   Unknowns involving PHI

Target **10--15 total rules**.
