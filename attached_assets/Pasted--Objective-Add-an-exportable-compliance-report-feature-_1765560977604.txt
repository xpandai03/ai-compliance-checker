**Objective**

Add an **exportable compliance report** feature that allows users to download a **deterministic AI Risk Assessment artifact** based on the current scan.

This report must be suitable for:

-   Internal compliance review

-   Sharing with legal / risk teams

-   Audit evidence

This feature **does not** imply legal compliance or legal advice.

* * * * *

**SCOPE & CONSTRAINTS (IMPORTANT)**
-----------------------------------

✅ Allowed:

-   Export **PDF** and **JSON**

-   Read-only content

-   Deterministic data only (no AI generation)

-   Clear disclaimers

-   Timestamping + versioning

❌ Not allowed:

-   No legal conclusions

-   No "pass/fail compliance"

-   No LLM reasoning

-   No modification of audit logic

-   No new rules

* * * * *

**IMPLEMENTATION PLAN (FOLLOW STEP BY STEP)**
---------------------------------------------

* * * * *

### **STEP 1 --- Define the Report Data Model**

Create a new file:

```
client/src/lib/report.ts
```

Define a structured export object:

```
export interface ComplianceReport {
  report_id: string
  generated_at: string
  tool_version: string

  model_profile: {
    model_name: string
    provider: string
    use_case: string
    user_type: string
  }

  provider_metadata: {
    fields: Record<string, {
      value: string | string[]
      source: string
      confidence: number
    }>
    overall_confidence: number
  }

  risk_assessment: {
    classification: "HIGH" | "LIMITED" | "MINIMAL" | "NEEDS_REVIEW"
    confidence_score: number
    triggered_rules: {
      rule_id: string
      description: string
      risk_level: string
    }[]
  }

  regulatory_grounding: {
    regulation: "EU AI Act"
    references: {
      ref: string
      title: string
      type: "Article" | "Annex" | "Recital"
      applied_because: string
    }[]
  }

  disclaimers: string[]
}
```

This model must be populated **only from existing computed data**.

* * * * *

### **STEP 2 --- Build a Report Generator Function**

In report.ts, export:

```
export function generateComplianceReport(
  modelProfile,
  findings,
  providerMetadata
): ComplianceReport
```

Requirements:

-   Generate a UUID for report_id

-   ISO timestamp for generated_at

-   Hardcode tool_version (e.g. v0.3-demo)

-   Do not infer or add new logic

-   This is a **pure function**

* * * * *

### **STEP 3 --- Add Export Controls to the UI**

In the **right pane (Audit Trail header or footer)** add:

-   Button: **Download Report**

-   Dropdown:

    -   Download as PDF

    -   Download as JSON

Place this near:

> "Audit completed deterministically"

This visually reinforces that the report is an **audit artifact**.

* * * * *

### **STEP 4 --- Implement JSON Export (First, Easiest)**

On click:

-   Call generateComplianceReport(...)

-   Serialize to JSON

-   Trigger browser download

Filename format:

```
ai-risk-assessment_<model>_<timestamp>.json
```

* * * * *

### **STEP 5 --- Implement PDF Export (Simple, Clean)**

Use a client-side PDF solution (basic is fine).

PDF layout (single column):

1.  **Title**

    -   "AI Risk Assessment Report"

    -   Subtitle: "Deterministic, EU AI Act--grounded"

2.  **Report Metadata**

    -   Report ID

    -   Generated at

    -   Tool version

3.  **Model Profile**

    -   Model

    -   Provider

    -   Use case

    -   User type

4.  **Provider Metadata**

    -   Table of fields

    -   Value | Source | Confidence

5.  **Risk Assessment**

    -   Classification (badge)

    -   Confidence score

    -   Triggered rules list

6.  **Regulatory Grounding**

    -   EU AI Act references

    -   For each:

        -   Article / Annex / Recital

        -   Title

        -   "Applied because ..."

7.  **Disclaimers (Required)**

    Include all of the following verbatim:

    -   "This report is generated by a deterministic rules-based system."

    -   "This report does not constitute legal advice."

    -   "Regulatory references are provided for traceability only."

    -   "This assessment does not certify compliance or non-compliance."

* * * * *

### **STEP 6 --- Preserve Legal & UX Integrity**

-   PDF must be **read-only**

-   No editable fields

-   No implied approval language

-   Keep tone factual and neutral
